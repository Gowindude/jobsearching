## 📌 Standing Preferences

These apply to every future update of this tracker — read before scraping, adding, or removing anything.

1. **Term: Spring 2027 or Summer 2027 preferred; year-round and no-explicit-date postings are OK too if recently posted (relaxed 2026-08-24).** Explicit Fall 2026 or Winter 2027 postings are still excluded from the open tables (wrong season, low odds of still being open by the time an application would land) — log those in Bucket B/Closed instead, don't delete the research. But a "year-round" program, or a posting that never states a term/year at all, is now fine to add to the main tables as long as it was posted recently (roughly within the last few weeks) — don't hold those back waiting for an explicit "Spring 2027"/"Summer 2027" string that may never appear.
2. **No Palantir SWE/FDSE roles.** Don't add or keep Palantir Software Engineer / Forward Deployed Software Engineer (FDSE) internships, including "Year at Palantir" SWE/FDSE tracks — dropped 2026-08-07 per explicit request. Other Palantir roles (e.g. Deployment Strategist) are still fine to track; Palantir otherwise remains a priority defense target.
3. **Location preference: SF Bay Area or LA-area (incl. El Segundo/Hawthorne/Torrance/Long Beach).** When sourcing new small/startup companies to add (Cold Email or Manual Check), weight toward these two hubs — e.g. Astranis, Apex Space, Antaris, Capella Space. This doesn't rule out strong role-interest fits elsewhere (Firefly in TX, dSPACE in MI are tracked for their GNC/sim relevance), but SF/LA should be the first place to look when adding companies just because they're "similar to X."
4. **Push to `origin main` by default after committing.** No need to ask before pushing routine tracker updates (adding/removing roles, fixing dead links, etc.) — this README is meant to stay live on GitHub. Still use judgment for anything unusual (force-push, branch changes, history rewrites).
5. **Target-company preference relaxed (2026-08-16).** No longer limiting scraping/sourcing effort to the Priority Targets list below — any company is worth tracking as long as the role itself is GNC, systems engineering, simulation/modeling, or otherwise 🎯-adjacent (see Role Interest Filter). The Priority Targets list still governs sort order (target-company rows and earlier-posted rows are kept near the top of each table) but no longer limits which companies get sourced.
6. **Within each table, sort target-company rows and earlier-posted-date rows toward the top.** Priority Target companies (see below) go first regardless of posting date; among the rest, older postings (closer to any deadline, more likely to close soon) rank above newer ones. "Posted: Unknown" rows are left in their existing relative position rather than guessed at.
7. **Check these job boards every run (added 2026-08-16):** [jobs.spacecrew.com/space-engineer-jobs](https://spacecrew.com/space-engineer-jobs) (filter to the "Internship" category — the "Load More" pagination is flaky in headless browsing, so click it directly via its element ref rather than by coordinate, and expect ~25-30 results to actually render even though it reports 100 total) and [jobs.spacecapital.com/jobs](https://jobs.spacecapital.com/jobs) (search box requires an actual click+type, not a `?query=` URL param — then set the Seniority filter to "Internship"; 477+ results, click "Load more" repeatedly). Both are broad multi-company aggregators, good for surfacing new GNC-adjacent companies outside the Priority Targets list (see preference #5) — cross-check any promising hit against the company's own careers page before adding, since aggregator listings can be stale (e.g. True Anomaly's GSE Engineering Intern, found 2026-08-16, no longer live on their own site).
8. **Every full sweep must directly browser-check every company in the Manual Check section — Priority, Secondary, Big Tech, eVTOL, Simulation/CAE, GNC & Simulation, Robotics & Hardware Startups, all of it — not a sample (added 2026-08-24).** Use the actual `claude-in-chrome` browser tools (or the Ashby/Greenhouse/Lever public JSON APIs directly via in-page `fetch()`), not WebFetch/WebSearch alone — WebFetch has repeatedly given wrong answers on large ATS pages (silently truncates/summarizes big JSON, undercounted Applied Intuition's board at "7 jobs" when it actually had 295; missed the entire 34-role Zipline Spring/Summer 2027 wave that only surfaced once queried live). If background/forked agents are used and the Chrome extension isn't connected in their session, that's a real gap, not an acceptable substitute — re-run those companies directly once a live browser is available, and don't report the sweep as complete until every Manual Check company has a same-run direct-browser (or verified public-API) check logged.

## 🎯 Role Interest Filter

Roles are tagged 🎯 when they match what I actually want to apply to. In priority order:

1. **GNC** — guidance, navigation & controls, autonomy/controls engineering
2. **Simulation & modeling** — CFD/FEA, physics simulation, digital twin, modeling & simulation roles
3. **General engineering** — broad "Engineering Intern" tracks not pinned to one hardware discipline (e.g. SpaceX/Blue Origin's general Engineering Internship)
4. **SWE / flight software** — software engineering, embedded/flight software, ground software, full-stack

Other technical roles (EE, ME, avionics hardware, propulsion, manufacturing, structures, test, RF, etc.) are still tracked since they're already verified-open and someone else scanning this list might want them, but they're **not tagged 🎯** — my background doesn't line up with them, so don't spend extra scraping/search effort chasing new postings in those categories specifically. When searching for new roles each run, weight effort toward finding more 🎯-eligible postings over expanding coverage of non-🎯 categories.

Several portals in the "Manual Check" table return Cloudflare/bot-detection challenges or empty responses to `curl` (RTX/Phenom, Stoke Space's client-rendered Greenhouse embed, iCIMS-based Joby, and any Workday tenant hit with a GET instead of the tenant's POST job-search API). 2. `tabs_context_mcp{createIfEmpty:true}` once, then `navigate` to each portal and `get_page_text` (wait a few seconds first — many of these render job lists client-side, and RTX shows a ~5s Cloudflare "Just a moment..." interstitial before the real page loads).
3. The first visit to a brand-new domain in a session can return "Permission denied for reading page content on this domain" from `get_page_text` — this is the Chrome extension's per-site permission gate, and it must be granted in the extension UI itself; it can't be pre-approved from the agent side. **Step 3 — Verify existing links:**

Greenhouse: `curl -s -o /dev/null -w "%{http_code}" <url>` — 302 to `?error=true` = closed.
Lever: `https://api.lever.co/v0/postings/<company>/<id>?mode=json` — 404 = closed. **Trust this over the HTML page** — `jobs.lever.co/<company>/<id>` is a client-rendered SPA shell that can return 200 with a correct `<title>` even after the underlying job is gone (the JS just never manages to fetch real content). Workday: `curl -s -o /dev/null -w "%{http_code}" -L <url>` — 200 = open.
If piping URLs from a file built with Python's `print()` on Windows/Git Bash, strip carriage returns first (`tr -d '\r'`) — a stray `\r` silently breaks every `curl` call in the loop with no useful error (curl just times out / returns `000`).

**Step 3.5 — Pull a "Posted" date for every role (required — every role row needs one):**

Each ATS exposes the original post date differently. Fetch it per-role when adding or re-verifying a listing:

- **Greenhouse**: `curl -s https://boards-api.greenhouse.io/v1/boards/<board>/jobs/<id>` → `first_published` field (ISO datetime, truncate to date). Caveat: some companies (Palantir, Figure have shown this) reuse an old requisition ID for a role they keep reposting — if `first_published`/`createdAt` is more than ~6 months stale relative to everything else on the same board, don't treat it as "this listing is old." Verify it's still live (200/non-404) and mark the date with a ⚠️ + one-line note instead of dropping it.
- **Lever**: `curl -s https://api.lever.co/v0/postings/<company>/<id>?mode=json` → `createdAt` field (epoch milliseconds — convert with `datetime.utcfromtimestamp(ms/1000)`).
- **Ashby**: `curl -s https://api.ashbyhq.com/posting-api/job-board/<board>` → find the job by `id` in the `jobs` array → `publishedAt` field.
- **Workday**: no reliable per-job API date found — the list endpoint's `postedOn` field is relative text ("Posted 8 Days Ago") tied to search relevance and doesn't reliably surface the specific role you're looking for even with an exact-phrase `searchText`. Mark Workday-sourced roles (Blue Origin, Draper, Boeing, etc.) as `Unknown` in the Posted column unless you can confirm the date another way (e.g. reading the "Posted On" text directly off the rendered page via Claude in Chrome).
- **iCIMS, Rippling, and other custom/JS-rendered boards** (Joby, Luminary Cloud): no API found — mark `Unknown`.
